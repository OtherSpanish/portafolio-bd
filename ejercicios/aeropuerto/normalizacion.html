Ejercicio · Aeropuerto

Normalización

De una planilla con redundancia a tablas en FNBC, usando datos reales del ejercicio.

Ver enunciado del ejercicio

Una aerolínea que opera en varios aeropuertos de Colombia necesita una base de datos para su operación.

  • Cada BASE (aeropuerto donde la aerolínea tiene operación) se identifica con un código IATA de tres letras y tiene nombre, ciudad y país.
  • Cada PILOTO tiene identificación, nombre, número de licencia, horas de vuelo acumuladas y uno o varios teléfonos. Está asignado a exactamente una base.
  • Cada AVIÓN se identifica por su matrícula y tiene modelo, fabricante y capacidad. Permanece en una base.
  • Un VUELO tiene un identificador, un código comercial (por ejemplo AV101), fecha, hora de salida y destino. Sale de una base y lo opera un único avión.
  • En cada vuelo trabajan uno o más pilotos con un rol (capitán o copiloto), y un piloto puede tripular muchos vuelos.
  • Los PASAJEROS se registran con identificación, nombre (nombres y apellidos), fecha de nacimiento y correo; su edad se calcula. Un pasajero reserva vuelos y en cada reserva se guarda el asiento y la clase.

Entidades del enunciado: Piloto, Pasajero y Base. Entidades inventadas para completar el problema: Avión y Vuelo.

Dependencias funcionales

Del enunciado y de los datos salen estas dependencias funcionales (X → Y: conociendo X se conoce un único Y):

DF1  id_vuelo → codigo, fecha, destino, matricula, base_origen
DF2  matricula → modelo
DF3  base_origen → ciudad_origen
DF4  documento → pasajero
DF5  documento →→ telefono  (dependencia multivaluada)
DF6  {id_vuelo, documento} → asiento, clase
DF7  {id_vuelo, asiento} → documento
DF8  {codigo, fecha} → id_vuelo

Llave candidata de la planilla: {id_vuelo, documento} (se elige como primaria). {id_vuelo, asiento} también es llave candidata por la DF7.

1FNPrimera forma normal (1FN)

Regla: todos los atributos son atómicos y no hay grupos repetitivos.

Acción: el grupo repetitivo telefonos sale a su propia tabla con la llave de quien lo tiene (documento).

Regla: en toda dependencia funcional no trivial X → Y, X es superllave.

Todas las tablas están en FNBC. El resultado coincide con las tablas obtenidas en la reducción a tablas (BASE, PERSONA/PASAJERO, TELEFONO_PERSONA, AVION, VUELO, RESERVA): un MER-E bien hecho produce tablas ya normalizadas, y la normalización sirve para comprobarlo.
