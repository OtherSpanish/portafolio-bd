Ejercicio · Aeropuerto

Álgebra relacional

Consultas sobre el aeropuerto con su expresión, su SQL y su resultado.

Ver enunciado del ejercicio

Una aerolínea que opera en varios aeropuertos de Colombia necesita una base de datos para su operación.

  • Cada BASE (aeropuerto donde la aerolínea tiene operación) se identifica con un código IATA de tres letras y tiene nombre, ciudad y país.
  • Cada PILOTO tiene identificación, nombre, número de licencia, horas de vuelo acumuladas y uno o varios teléfonos. Está asignado a exactamente una base.
  • Cada AVIÓN se identifica por su matrícula y tiene modelo, fabricante y capacidad. Permanece en una base.
  • Un VUELO tiene un identificador, un código comercial (por ejemplo AV101), fecha, hora de salida y destino. Sale de una base y lo opera un único avión.
  • En cada vuelo trabajan uno o más pilotos con un rol (capitán o copiloto), y un piloto puede tripular muchos vuelos.
  • Los PASAJEROS se registran con identificación, nombre (nombres y apellidos), fecha de nacimiento y correo; su edad se calcula. Un pasajero reserva vuelos y en cada reserva se guarda el asiento y la clase.

Entidades del enunciado: Piloto, Pasajero y Base. Entidades inventadas para completar el problema: Avión y Vuelo.

EJ 2Proyección (π) + Selección + Reunión natural (⋈)

Nombres, apellidos y horas de vuelo de los pilotos con más de 10.000 horas.

Álgebra relacional
πnombres, apellidos, horas_vuelo( σhoras_vuelo > 10000( PILOTO ⋈ PERSONA ) )

PILOTO y PERSONA comparten solo documento, así que la reunión natural une por esa columna.

Ver SQL equivalente
SELECT pe.nombres, pe.apellidos, pi.horas_vuelo
FROM piloto pi
JOIN persona pe ON pe.documento = pi.documento
WHERE pi.horas_vuelo > 10000;

EJ 3Reunión natural (⋈)

Matrícula, modelo y código de los vuelos que salen de Bogotá (BOG).

Álgebra relacional
πid_vuelo, codigo, matricula, modelo( σcodigo_base_origen = 'BOG'( VUELO ) ⋈ AVION )

Seleccionar antes de reunir es una optimización clásica: se reúnen menos tuplas.

Ver SQL equivalente
SELECT v.id_vuelo, v.codigo, a.matricula, a.modelo
FROM vuelo v
JOIN avion a ON a.matricula = v.matricula
WHERE v.codigo_base_origen = 'BOG'
ORDER BY v.id_vuelo;

EJ 6Unión (∪)

Documentos de todas las personas a bordo del vuelo 1 (tripulación y pasajeros).

Álgebra relacional
πdocumento( σid_vuelo = 1( TRIPULA ) ) ∪ πdocumento( σid_vuelo = 1( RESERVA ) )

Las dos relaciones son compatibles en unión: una sola columna del mismo dominio.

Ver SQL equivalente
SELECT documento FROM tripula WHERE id_vuelo = 1
UNION
SELECT documento FROM reserva WHERE id_vuelo = 1
ORDER BY documento;

EJ 7División (÷)

Pasajeros que reservaron todos los vuelos con destino a Cartagena.

Álgebra relacional
R ← πdocumento, id_vuelo( RESERVA )
S ← πid_vuelo( σdestino = 'Cartagena'( VUELO ) )
πdocumento, nombres, apellidos( ( R ÷ S ) ⋈ PERSONA )

S = {1, 3, 4}. SQL no tiene operador de división: se escribe con doble NOT EXISTS (“no existe un vuelo a Cartagena que el pasajero no haya reservado”).

Ver SQL equivalente
SELECT pe.documento, pe.nombres, pe.apellidos
FROM persona pe
WHERE pe.documento IN (SELECT documento FROM pasajero)
  AND NOT EXISTS (
      SELECT 1 FROM vuelo v
      WHERE v.destino = 'Cartagena'
        AND NOT EXISTS (
            SELECT 1 FROM reserva r
            WHERE r.documento = pe.documento
              AND r.id_vuelo = v.id_vuelo));

EJ 8Renombre (ρ) y autorreunión

Parejas de pilotos asignados a la misma base.

Álgebra relacional
πP1.documento, P2.documento, P1.codigo_base( ρP1( PILOTO ) ⋈P1.codigo_base = P2.codigo_base ∧ P1.documento < P2.documento ρP2( PILOTO ) )

La condición P1.documento < P2.documento evita parejas repetidas (A,B)/(B,A) y parejas de un piloto consigo mismo.

Ver SQL equivalente
SELECT p1.documento AS piloto_1, p2.documento AS piloto_2, p1.codigo_base
FROM piloto p1
JOIN piloto p2 ON p1.codigo_base = p2.codigo_base
             AND p1.documento < p2.documento;
Resultado

EJ 10Consulta combinada

Nombre de los capitanes de los vuelos con destino a Cartagena, con el código y la fecha del vuelo.

Álgebra relacional
πcodigo, fecha, nombres, apellidos( σrol = 'CAPITAN'( TRIPULA ) ⋈ σdestino = 'Cartagena'( VUELO ) ⋈ PERSONA )
Ver SQL equivalente
SELECT v.codigo, v.fecha, pe.nombres, pe.apellidos
FROM tripula t
JOIN vuelo v    ON v.id_vuelo = t.id_vuelo
JOIN persona pe ON pe.documento = t.documento
WHERE t.rol = 'CAPITAN'
  AND v.destino = 'Cartagena'
ORDER BY v.fecha;
